# Working in Dark Engine

Work from the repository root. The legacy engine lives under `Dark Engine/Source/Runtime/`. The Linux migration uses C++23, CMake, Ninja, GCC and Clang. Read the [target architecture](docs/architecture-target.md), locate the current phase in the [migration plan](docs/migration-plan.md), then execute one [task specification](docs/tasks/) at a time.

- Treat every `ThirdParty/` tree as a black box. The only permitted reads there are files named exactly `CMakeLists.txt`. Never open, grep, index or traverse dependency source, headers, shaders or binaries. Never propose or make edits inside that tree. Infer usage from first-party includes and calls, then check wrapper target declarations. Start searches in named first-party modules. To locate tracked wrapper files use `git ls-files -- ':(glob)Dark Engine/Source/ThirdParty/**/CMakeLists.txt'`.
- Exclude `build/`, `.git/`, `assets/`, `Cache/`, `.cache/` and `.github/` from repository discovery. Avoid unscoped recursive searches, source globs and configuration of the legacy graph. Its root globs enter the vendor tree and its Core configuration generates a tracked source file.
- Respect the task's allowed files, prerequisites and definition of done. Preserve existing user changes. For documentation-only work, limit writes to root `AGENTS.md` and the specified Markdown under `docs/`. For implementation tasks, use their explicit allowlists. Record the concrete blocker if a prerequisite is missing.
- Keep SDL3 and native handles private to platform integration. Keep Vulkan behind RHI and retain DX12 as contract evidence. Admit portable engine behavior one tested slice at a time. Avoid propagating Win32, COM ownership, global backend selection or unused UE-style macros into new public headers.
- Use manifest-mode vcpkg with the checked-in baseline, supplied through `VCPKG_ROOT`. Use system Vulkan on Linux. Keep compiler flags and dependencies target-scoped. Task 01 introduces the presets and CTest. From then on, run `cmake --preset linux-clang`, `cmake --build --preset linux-clang` and `ctest --preset linux-clang -L cpu --output-on-failure --no-tests=error` from the root. Repeat with `linux-gcc` and run CPU tests with `linux-sanitize` for ASan/UBSan.
- Run the assigned spec's exact checks, including display or GPU tests when specified. Report the compiler, display backend, result and any unverified gate. A skipped test or an unavailable compositor cannot establish a passing graphics milestone.
